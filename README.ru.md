# Менеджер расширений OpenCode

**Русский** | [English](README.md) | [简体中文](README.zh.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [日本語](README.ja.md) | 繁體中文 | 한국어 | Italiano | Polski | Türkçe | Українська

Плагин для OpenCode Desktop, который добавляет в «Настройки» отдельную страницу **«Менеджер расширений»**. Через неё можно управлять MCP-серверами, плагинами и навыками, не редактируя `opencode.json` вручную.

## Что умеет

- **MCP-серверы**: локальные (`command`, `cwd`, переменные окружения) и удалённые (`url`, заголовки, OAuth-блок); включение и выключение без удаления записи. Значения переменных окружения и заголовков скрыты в списке; кнопка с глазом показывает их, а **«Скопировать безопасный конфиг»** заменяет значения на `***`. Если секретоподобный заголовок хранится в проектной конфигурации, появляется предупреждение.
- **Плагины**: npm-пакеты, локальные папки и записи-исключения вида `-package`; параметры плагина передаются как JSON-объект.
- **Маркетплейсы плагинов**: встроенный каталог Anthropic `anthropics/claude-plugins-official` доступен сразу, но ничего из него не устанавливается автоматически. Можно добавить свои маркетплейсы по GitHub-ссылке, URL или локальной папке, при необходимости закрепить ветку, тег или коммит, открыть каталог, установить плагин, обновить, отключить, удалить или откатить его. Для сторонних маркетплейсов показывается подтверждение и значок «сторонний»; каталог можно обновлять автоматически каждые 5 минут, пока раздел открыт.
- **Навыки**: папка с `SKILL.md` или отдельный файл `<id>.md`; полное редактирование текста, переименование, включение и отключение.
- **Две области**: глобальная (`~/.config/opencode`) и проектная (ближайшая папка `.opencode`, как у самого OpenCode).
- **Безопасная запись**: комментарии и форматирование JSONC сохраняются, перед каждой записью создаётся `.bak`, запись атомарная. При синтаксической ошибке в файле изменения блокируются.
- **Неизвестные поля сохраняются**: если в конфиге MCP-сервера есть поля, которых нет в форме, они остаются на месте.
- **Статусы MCP**: страница показывает, подключён сервер, запускается, выключен или требует входа.
- **Локализация**: интерфейс на английском, русском, упрощённом и традиционном китайском, испанском, французском, немецком, японском, корейском, итальянском, польском, турецком и украинском. Остальные языки используют английский. Переведённые README есть для английского, русского, упрощённого китайского, испанского, французского, немецкого и японского; для остальных языков интерфейса README пока нет.
- **Диагностика**: проверяет ошибки JSONC и разбора, совпадающие имена MCP в глобальной и проектной областях, повторяющиеся записи плагинов, некорректные или нечитаемые записи MCP и плагинов, упавшие MCP-серверы и серверы, требующие входа, отсутствующие файлы конфигурации и отсутствующие или недоступные папки навыков. Безопасные действия: запуск проверки, показ путей, повторное подключение упавших MCP, копирование `opencode mcp auth <server>` и удаление повторяющихся записей плагинов через существующий RPC с подтверждением. Конфигурацию сама не переписывает.
- **Центр обновлений**: проверяет плагины маркетплейсов, пакетные плагины npm/GitHub и импорт из Claude Code по их исходникам. Обновляет каждый элемент отдельно и показывает результат по каждому. Во время обновления видны прогресс по элементам и источникам: «Обновление X из Y: имя». MCP-серверы и навыки, добавленные вручную, не имеют источника и пропускаются.
- **Поиск, массовые действия и навигация**: глобальный поиск по MCP-серверам, плагинам, навыкам, маркетплейсам, их каталогам и установленным плагинам с фильтрами «Все / MCP / Плагины / Навыки / Маркетплейсы» и переходом к найденной строке. Множественный выбор с «Выбрать все», счётчиком и массовыми включением, отключением и удалением для MCP и навыков, а также массовым удалением плагинов. Действия используют существующие RPC, выполняются последовательно, показывают прогресс и итог по успехам и ошибкам. Для MCP, плагинов, навыков и установленных плагинов есть сортировка, которая запоминается для каждого списка. Загрузка показывается скелетон-строками, а Alt+1 … Alt+6 переключают вкладки, пока открыта страница настроек.
- **О плагине и самообновление**: показывает версию плагина, версию OpenCode, папку установки, ветку и коммит. Git-репозиторий обновляется из официального GitHub через fast-forward, при необходимости ставит зависимости и пересобирает GUI. Показывает новые коммиты, хранит историю обновлений и откатов, поддерживает каналы `main`/`stable` и автоматические проверки. Пакетные установки обновляются через сервис плагинов OpenCode. После обновления самого плагина нужен перезапуск.

## Маркетплейсы

Маркетплейс — это GitHub-репозиторий (или локальная папка) с файлом `.claude-plugin/marketplace.json`. Встроенный каталог Anthropic уже добавлен, но установка всегда выполняется вручную.

Из плагина маркетплейса в OpenCode переносятся совместимые части:

- MCP-серверы из `.mcp.json` или `mcpServers`;
- навыки из `skills/**/SKILL.md`;
- OpenCode-плагины, если репозиторий сам является плагином OpenCode.

Если у навыка нет корректного YAML frontmatter, он показывается в диалоге установки отдельно. Можно включить **«Адаптировать автоматически»** — менеджер добавит минимальный frontmatter с именем папки и первой строкой как описанием.

Команды, агенты, хуки и LSP Claude Code не поддерживаются — они показываются в предупреждении при установке.

Установленные из маркетплейсов плагины хранятся в реестре `~/.config/opencode/extensions-manager.json`. Их можно включать, отключать, обновлять и удалять. Удаление убирает только то, что добавил менеджер.

При добавлении стороннего маркетплейса менеджер сначала спрашивает подтверждение: его плагины могут добавлять MCP-серверы, навыки и код. Поле **Ref** необязательно: пустое значение использует ветку по умолчанию, а ссылки с `/tree/<ref>` продолжают работать. После успешного обновления у установленного плагина появляется кнопка отката к предыдущей версии или коммиту; если маркетплейс больше не содержит старые файлы, откат завершается ошибкой до изменения конфигурации.

Если вставить ссылку на обычный GitHub-репозиторий, который не является маркетплейсом, менеджер попробует определить MCP-сервер или плагин OpenCode и предложит установить его.

Ссылка `https://github.com/upstash/context7` тоже работает: у этого репозитория есть собственный `.claude-plugin/marketplace.json`, поэтому он добавляется как отдельный маркетплейс, а `context7` устанавливается из его каталога. В итоге в конфигурацию попадает удалённый MCP `https://mcp.context7.com/mcp`.

## Импорт из Claude Code

Менеджер читает кэш плагинов Claude Code (`~/.claude/plugins/cache` или `$CLAUDE_CONFIG_DIR/plugins/cache`). Раздел сканирует кэш при открытии; кнопка **Scan again** обновляет список. Сначала показывается только предпросмотр: какие MCP-серверы, навыки и плагины OpenCode можно перенести, а какие части Claude Code не поддерживаются. У каждого кандидата виден исходный путь. Установка запускается вручную для выбранных плагинов, исходные папки только читаются.

Импорт использует то же транзакционное сохранение и отпечатки владения, что и установка из маркетплейса. Поэтому удаление и отключение убирают только те артефакты, которые не были изменены после установки.

## Центр обновлений

**Центр обновлений** на вкладке «Обзор» проверяет установленные элементы по источнику, из которого они появились:

- плагины маркетплейсов — по их маркетплейсу;
- пакетные плагины npm и GitHub — через сервис плагинов OpenCode;
- импорт из Claude Code — по версии плагина в кэше.

Кнопка **Проверить обновления** показывает устаревшие элементы с текущей и последней версией или коммитом, если они известны. Кнопка **Обновить все устаревшие** запускает пакетное обновление: ошибка одного элемента не прерывает остальные, а результаты по каждому показывают успех, ошибку и сохранённые артефакты маркетплейса, которые больше не совпадают с отпечатком установки.

MCP-серверы и навыки, добавленные вручную, не имеют источника обновления и не изменяются.

## О плагине и самообновление

Вкладка **О плагине** показывает версию плагина, версию OpenCode, репозиторий, лицензию, папку установки, ветку и текущий коммит.

- **Канал** выбирает `main` (последний коммит, по умолчанию) или `stable` (старший semver-тег релиза на origin, например `v0.2.0` или `0.2.0`). Stable получает теги из официального remote и не применяет обновление, если тегов нет.
- **Частота проверки** управляет автопроверками при открытии страницы настроек: при запуске, ежедневно (не чаще раза в 24 часа) или вручную. Вкладка «О плагине» показывает предупреждающий бейдж, пока доступно обновление; кнопка **Проверить обновления** работает всегда.
- **Проверить обновления** сравнивает Git-репозиторий с выбранной целью и отдельно спрашивает сервис плагинов OpenCode о пакетной установке. **Что нового** показывает до 20 коммитов между репозиторием и целью.
- **Обновить плагин** делает fast-forward чистой ветки `main` или переводит на выбранный stable-тег, запускает `npm install`, если изменились файлы пакета, и пересобирает GUI. Пакетные установки обновляются через сервис плагинов OpenCode.
- **История обновлений** сохраняет успешные обновления и откаты в `extensions-manager-updates.json` в глобальной папке конфигурации (последние 20 записей). Откатить запись обновления можно только на чистом официальном `main`, если коммит ещё есть локально и является предком `HEAD`: репозиторий сбрасывается, зависимости и GUI пересобираются, а ошибки показываются без сокрытия нового состояния.
- Локальные изменения, другая ветка, неофициальный remote или разошедшаяся история блокируют автообновление, чтобы не перезаписать работу.
- После обновления перезапустите OpenCode, чтобы серверная часть и GUI работали на одной версии.

## Диагностика

Раздел **Диагностика** проверяет текущую конфигурацию и показывает найденные проблемы, ничего не изменяя:

- Некорректный JSONC и ошибки разбора, а также недоступные для чтения файлы конфигурации.
- Файлы конфигурации, которые ещё не созданы.
- Имена MCP-серверов, заданные одновременно в глобальной и проектной областях.
- Повторяющиеся записи плагинов, а также записи, которые не являются ни строкой пакета, ни объектом пакета.
- Записи MCP, которые не являются ни локальной командой, ни удалённым URL, включая локальные записи без команды и удалённые без URL.
- MCP-серверы со статусом «ошибка» или «нужен вход».
- Отсутствующие или недоступные для чтения папки навыков.

Безопасные действия:

- **Запустить проверку** обновляет результаты диагностики.
- **Показать файл конфигурации**, **Показать папку конфигурации**, **Показать папку навыков** и **Показать папку проекта** открывают путь в файловом менеджере.
- **Повторить** заново подключает упавший MCP-сервер.
- **Войти** копирует `opencode mcp auth <server>` для серверов, которым нужна авторизация.
- **Удалить #N** удаляет повторяющуюся запись плагина через существующий RPC менеджера — после подтверждения и с резервной копией `.bak`.

Диагностика никогда не переписывает конфигурацию сама. Исправления, требующие правки конфигурации, например совпадающие имена MCP в двух областях, некорректные записи или права на папку навыков, только показываются — их нужно исправить вручную.

## OAuth для MCP

В редакторе удалённого MCP-сервера есть три режима OAuth:

- **Автоматически** — поле `oauth` не записывается, OpenCode сам пытается зарегистрировать OAuth-клиент.
- **Свой OAuth-клиент** — можно задать `client_id`, `client_secret`, `scope`, `callback_port`, `redirect_uri` и `auth_server_metadata_url`.
- **Выключен** — записывается `oauth: false`, удобно для серверов с API-ключом в заголовках.

Сам вход через браузер выполняет OpenCode:

```powershell
opencode mcp auth context7
```

Команда открывает браузер и сохраняет токены в `~/.local/share/opencode/mcp-auth.json`. Посмотреть статус и выйти можно так:

```powershell
opencode mcp list
opencode mcp logout context7
```

В менеджере у сервера со статусом «нужен вход» есть кнопка, которая копирует команду `opencode mcp auth <имя>`. Сам браузер менеджер не открывает: GUI API OpenCode не предоставляет отдельный вызов OAuth.

Для Context7 OAuth не обязателен. Если нужен свой аккаунт или повышенные лимиты, проще выключить OAuth и добавить заголовок:

```text
CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}
```

или

```text
Authorization=Bearer <ключ>
```

Ключ выдаётся на `https://context7.com/dashboard`.

## Установка

1. Соберите GUI:

   ```powershell
   npm install
   npm run build
   ```

2. Подключите папку плагина в глобальном конфиге `C:\Users\<вы>\.config\opencode\opencode.json`:

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "plugins": [
       "C:\\Users\\<вы>\\Documents\\Opencode Plugin Manager"
     ]
   }
   ```

3. Перезапустите OpenCode Desktop.

Страница появится в **Настройки → Менеджер расширений**. Её же можно открыть из палитры команд.

## Разработка

```powershell
npm run typecheck   # проверка типов
npm run smoke       # серверная логика на временном проекте
npm run smoke:marketplace  # маркетплейс, установка и удаление на локальном каталоге
npm run build       # сборка dist/gui-experimental.cjs
npm run dev         # пересборка GUI при изменениях
```

После изменения GUI-кода нужен `npm run build` и перезапуск приложения. Серверная часть перезагружается по watcher'у OpenCode, но если плагин продолжает работать по-старому, перезапустите Desktop.

## Ограничения

- OAuth MCP выполняется командой `opencode mcp auth <имя>` (OpenCode также запускает вход автоматически при первом использовании). Менеджер только создаёт и правит конфигурацию; для сервера со статусом «нужен вход» есть кнопка, копирующая команду.
- Claude-специфичные параметры вроде `?client=claude-code-plugin` автоматически убираются из remote MCP URL при загрузке плагина и при установке из маркетплейса.
- Навыки с корректным frontmatter импортируются как есть; навыки без frontmatter по умолчанию пропускаются, но в диалоге установки их можно адаптировать автоматически.
- Навыки сканируются на одном уровне: `<skillsDir>/<id>/SKILL.md` и `<skillsDir>/<id>.md`. Отключённые навыки лежат в `<skillsDir>/.disabled`.
- Проверка обновлений опирается на версию в метаданных или на разрешённый SHA коммита GitHub. Если локальный маркетплейс меняет файлы, не меняя ни версию, ни коммит, плагин считается актуальным.
- Диагностика не переписывает конфигурацию сама, за исключением явного действия по удалению повторяющейся записи плагина.
- Проектная область использует ближайшую найденную папку `.opencode`; если её нет, при первом изменении будет создана `<проект>/.opencode/opencode.json`.
- Плагин рассчитан на OpenCode 2.2.x и использует экспериментальный GUI API (`./gui-experimental`).
